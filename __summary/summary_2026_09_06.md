# Podsumowanie Projektu: Production-Grade Project Management API

Oto szczegółowe podsumowanie dotychczasowych prac nad budową asynchronicznego API do zarządzania projektami i zadaniami. 

---

## 1. Przegląd i Cel Projektu
Stworzenie produkcyjnego, asynchronicznego API w języku Python z wykorzystaniem najnowszych standardów rynkowych, charakteryzującego się czystą architekturą wielowarstwową (*Clean Architecture*) oraz pełnym rozdzieleniem odpowiedzialności (od bazy danych po sieć).

---

## 2. Stos Technologiczny & Architektura
* **Framework**: FastAPI (asynchroniczny).
* **Baza Danych**: PostgreSQL.
* **ORM**: SQLAlchemy 2.0 (w trybie asynchronicznym z `psycopg` / `psycopg_async` oraz fabryką `async_sessionmaker`).
* **Walidacja & Schematy**: Pydantic v2 (`ConfigDict(from_attributes=True)`, `Field`, dziedziczenie bazowe).
* **Migracje & Automatyzacja**: Alembic + wyzwalacze SQL (triggers) aktualizujące `updated_at`.
* **Wzorce Architektoniczne**: 
  * *Repository Pattern* (izolacja dostępu do danych).
  * *Service Layer* (w trakcie wdrażania – izolacja logiki biznesowej).
  * *Dependency Injection* (wstrzykiwanie zależności przez `fastapi.Depends`).

---

## 3. Postęp i Zrealizowane Kamienie Milowe

### A. Baza Danych i Modele (`app/db/`)
* Skonfigurowano asynchroniczny silnik `create_async_engine` oraz generator sesji `get_db()` w `app/db/database.py`.
* Utworzono modele SQLAlchemy:
  * **`Project`**: `id`, `name`, `description`, `created_at`, `updated_at`, relacja z `tasks`.
  * **`Task`**: `id`, `title`, `description`, `priority` (Enum), `status` (Enum), `due_date`, `completed_at`, `project_id` (FK z wyczyszczeniem/kaskadą), `created_at`, `updated_at`.

### B. Schematy Pydantic (`app/schemas/`)
* **`task.py`**:
  * `TaskBase` z ograniczeniami długości `title` (`Field(..., min_length=1, max_length=100)`) i obiektami `PriorityEnum`/`StatusEnum`.
  * `TaskCreate` z wymaganym `project_id`.
  * `TaskUpdate` z w pełni opcjonalnymi polami (`PATCH`).
  * `TaskResponse` z mapowaniem `from_attributes=True`.
* **`project.py`**:
  * `ProjectBase`, `ProjectCreate`, `ProjectUpdate` (wykluczające ręczną zmianę dat).
  * `ProjectResponse` oraz `ProjectWithTasksResponse` obsługujące zagnieżdżoną listę `list[TaskResponse]`.

### C. Warstwa Repozytoriów (`app/repositories/`)
* **`ProjectRepository`**: zaimplementowano metody `get_by_id`, `create`, `get_all`, `update` (z `exclude_unset=True`), `delete`.
* **`TaskRepository`**: zaimplementowano `get_by_id`, `create`, `get_all_by_project_id`, `update`, `delete`.

### D. Warstwa Endpointów / Routery (`app/api/v1/endpoints/`)
* **`projects.py`**: pełen CRUD dla projektów na przedrostku `/api/projects`.
* **`tasks.py`**: 
  * Rozwiązano konflikt routingu w `GET` (użycie parametru zapytania `?project_id=...`).
  * Walidacja istnienia projektu przed utworzeniem lub przeniesieniem zadania.
* **`app/main.py`**: zarejestrowano routery, przetestowano działanie API poprzez Swagger UI (`/docs`).

Instrukcja do wykonania:
Stwórz plik app/core/exceptions.py:
Zdefiniuj podstawową klasę wyjątku oraz wyjątek braku projektu:

Python
class BusinessException(Exception):
    pass

class ProjectNotFoundException(BusinessException):
    def __init__(self, project_id: int):
        self.project_id = project_id
        super().__init__(f"Project with ID {project_id} was not found.")
Napisz klasę ProjectService w app/services/project_service.py:

Inicjalizacja (__init__): Przyjmuje project_repo: ProjectRepository i zapisuje go w self.project_repo.

get_project_by_id(project_id: int) -> Project: Wywołuje repozytorium. Jeśli projekt nie istnieje (None), rzuca ProjectNotFoundException(project_id). W przeciwnym razie zwraca projekt.

get_all_projects() -> list[Project]: Zwraca wszystkie projekty z repozytorium.

create_project(project_data: ProjectCreate) -> Project: Przekazuje dane do repozytorium i zwraca nowo utworzony projekt.

update_project(project_id: int, project_data: ProjectUpdate) -> Project: Najpierw pobiera projekt (używając get_project_by_id), a następnie aktualizuje go przez repozytorium.

delete_project(project_id: int) -> None: Najpierw pobiera projekt, a następnie usuwa go przez repozytorium.
